# P08-Spatial-Benchmarking-Analysis-for-publication

Analysis repository for spatial transcriptomics profiling of tertiary lymphoid structures (TLS) and high endothelial venules (HEV) in breast cancer using Visium, Visium HD, and Xenium platforms.

Link to Project description shared doc: [https://docs.google.com/document/d/1iX6YIyb9QG2PgjWokKXowN9cFGbwofTZ/edit?usp=sharing&ouid=108068971437548737290&rtpof=true&sd=true](https://docs.google.com/document/d/1iX6YIyb9QG2PgjWokKXowN9cFGbwofTZ/edit?usp=sharing&ouid=108068971437548737290&rtpof=true&sd=true)

## Getting the data

All input data are tracked as DVC imports that point directly at the public archives the data were deposited in (Zenodo, BioImage Archive), so no access to our own storage is needed. `dvc pull` fetches each file from the archive and verifies it against the checksum pinned in this repository.

```bash
git clone https://github.com/swarbricklab/P08-Spatial-Benchmarking-Analysis-for-publication.git
cd P08-Spatial-Benchmarking-Analysis-for-publication

conda env create -f environment/EDF/data-access.yaml
conda activate data-access
archivefs dvc enable    # once per environment: lets DVC resolve chiro://, zenodo://, bia:// and geo:// URLs
archivefs dvc status    # should report "installed: True"

dvc pull data/pathology_annotations.dvc    # pull only what you need
```

- Pull individual `.dvc` files rather than running a bare `dvc pull` — together they total ~1.4 TB. See [data/README.md](data/README.md#data-availability) for what each one contains and its size.
- Run `dvc` from inside the repository: the archive manifests the pins refer to live in `.chirograph/`.
- `Unsupported URL type chiro://` means `archivefs dvc enable` has not been run in the active environment.
- The ssh remote in `.dvc/config` is our internal cache and is not needed to pull the data.

## Repository Structure

### [config/](config/)
Configuration files including sample sheets (organized by platform and tissue type), parameter files (`params.sh`), and donor ID mappings used throughout the analysis workflows.

### [data/](data/)
Input data including AnnData objects, H&E images (OME-TIFF format), and pathology annotations. Files are organized by platform (Visium, Visium HD, Xenium) and tracked with DVC as imports from the public archives (see [Getting the data](#getting-the-data)). See [data/README.md](data/README.md) for details and [docs/tree.txt](docs/tree.txt) for a snapshot of the data organization.

### [environment/](environment/)
Conda environment YAML files for reproducible software environments. Different environments were used for various analysis steps and platforms.

### [resources/](resources/)
Reference data including curated gene signatures, cell type hierarchies, standardized color palettes, and tissue metadata. See [resources/README.md](resources/README.md) for details.

### [results/](results/)
Analysis outputs generated by scripts including processed data tables, differential expression results, signature scores, and other computational results. Cell type mapping results (deconvolution and label transfer) can be pulled from Zenodo with `dvc pull results/02_cell_type_mapping.dvc` to run downstream analyses without re-running the cell type mapping step. See [docs/tree.txt](docs/tree.txt) for the expected file organization.

### [scripts/](scripts/)
All analysis scripts organized into sequential workflows (preprocessing, cell type mapping, TLS niche discovery, vascular microenvironment analysis, xenium mechanisms) and figure generation scripts. Includes bash scripts for HPC job submission. See [scripts/README.md](scripts/README.md) for details.
